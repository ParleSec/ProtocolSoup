## What this requires

OID4VCI 1.0 Section 8.3 says "If the Credential Issuer is able to immediately issue the requested Credentials, it MUST respond with the HTTP status code 200". The body uses `credentials`, which "Contains an array of one or more issued Credentials". "The elements of the array MUST be objects", and each object has a REQUIRED `credential` member holding one issued Credential. `credentials` "MUST NOT be used if the transaction_id parameter is present", which is the deferred case answered with HTTP 202.

## Why it exists

One response can carry several Credentials, one for each key in `proofs`. A single array shape for one or many Credentials means a Wallet has one parsing path, and the number of entries can be compared with the number of keys it sent. Pre-Final drafts used a singular `credential` member. A Wallet and an issuer that disagree on the shape lose the Credential even though issuance succeeded.

## What non-compliance looks like

The issuer returns `{"credential": "..."}` at the top level, returns an empty `credentials` array with HTTP 200, or puts bare strings in the array instead of objects. A Final Wallet finds no Credential to store. The opposite mistake is a Wallet that still reads the singular member and ignores `credentials`.

## How ProtocolSoup tests it

The issuer's `handleCredential` in `handlers.go` returns HTTP 200 with `credentials` holding one `{"credential": ...}` object per proof key, plus a `notification_id`. A deferred grant gets HTTP 202 with only `transaction_id` and `interval`. The hosted wallet's `credentialResponseValues` in `cmd/walletharness/main.go` requires `credentials` to be a non-empty array of objects that each have `credential`, and rejects any other shape.

`TestCredentialResponseValueRequiresFinalCredentialsArray` is a wallet-side unit test. It asserts that a one-entry `credentials` array yields the Credential value, and that a body with only the singular `credential` member is rejected. It does not call the issuer and does not try an empty array. The issuer's response shape is asserted elsewhere, for example by `TestAuthorizationDetailsIssuesTokenBoundCredentialIdentifiers` under CI-007, which checks that no singular `credential` member is returned.
