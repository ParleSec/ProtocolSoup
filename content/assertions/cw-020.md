## What this requires

Section 12.2.2 tells the issuer to publish metadata "at the path formed by inserting the string /.well-known/openid-credential-issuer into the Credential Issuer Identifier between the host component and the path component, if any." For the wallet: "To fetch the Credential Issuer Metadata, the Wallet MUST send an HTTP request using the GET method and the path formed following the steps above."

The section's own examples: `https://issuer.example.com/tenant` is fetched from `https://issuer.example.com/.well-known/openid-credential-issuer/tenant`, and `https://tenant.issuer.example.com` from `https://tenant.issuer.example.com/.well-known/openid-credential-issuer`. The well-known string goes after the host, not on the end of the identifier.

## Why it exists

One issuer host can serve several tenants, each with its own identifier path. Insertion gives each tenant its own metadata location while keeping every well-known document under the host's `/.well-known/` namespace. The identifier also has to be recoverable from the URL exactly, because Section 12.2.4 compares the metadata's `credential_issuer` with the identifier "into which the well-known URI string was inserted".

## What non-compliance looks like

A wallet appends the string in the OpenID Connect Discovery style, requesting `https://issuer.example.com/tenant/.well-known/openid-credential-issuer`, and gets a 404 from a compliant multi-tenant issuer. A wallet that tries the inserted URL and then falls back to the appended one may load a document the issuer never published at the specified location. Dropping a trailing slash from the identifier's path asks for a different URL from the one the issuer published.

## How ProtocolSoup tests it

`resolveExternalIssuerMetadata` builds the URL with `wellKnownMetadataURLCandidates` and sends a GET with `Accept: application/json`. For `openid-credential-issuer` the function removes any query and fragment, inserts the string between host and path, keeps a trailing slash on the path, and returns that single URL with no appended fallback. An identifier whose path is only `/` is the exception: it yields `/.well-known/openid-credential-issuer` without a trailing slash.

`TestWellKnownMetadataURLCandidatesWithIssuerPath` asserts that `https://issuer.example/oid4vci` maps to `https://issuer.example/.well-known/openid-credential-issuer/oid4vci`. `TestWellKnownMetadataURLCandidatesPreserveCredentialIssuerTrailingSlash` asserts that a path ending in `/` keeps its slash and that exactly one candidate is returned. `TestWellKnownMetadataURLCandidatesStripOAuthASTrailingSlash` checks the contrasting `oauth-authorization-server` case, where RFC 8414 Section 3.1 removes the trailing slash, also with one candidate. The tests cover URL construction; that the request uses GET is visible in the code but not asserted.
