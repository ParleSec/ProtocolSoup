## What this requires

In Section 4.1.1 the `tx_code` object in a pre-authorized grant indicates "that a Transaction Code is required if present, even if empty". The same definition says: "If the Wallet decides to use the Pre-Authorized Code Flow, the Transaction Code value MUST be sent in the tx_code parameter with the respective Token Request as defined in Section 6.1." Section 6.1 repeats it from the Token Request side: the value "MUST be present if a tx_code object was present in the Credential Offer (including if the object was empty)."

An empty object, `"tx_code": {}`, therefore counts. It gives the wallet no `length`, `description` or `input_mode` hints, but the wallet still has to collect a code from the End-User and send it.

## Why it exists

Section 4.1.1 states the purpose: "The Transaction Code is intended to bind the Pre-Authorized Code to a certain transaction to prevent replay of this code by an attacker that, for example, scanned the QR code while standing behind the legitimate End-User." Section 13.6.1 explains that a Pre-Authorized Code is not bound to a session the way PKCE binds an authorization code, so a second value delivered over another channel is what stops a copied QR code from being redeemed elsewhere.

## What non-compliance looks like

A wallet treats `"tx_code": {}` as absent because it has no fields, or redeems the code without prompting the user. The Token Request carries only `grant_type` and `pre-authorized_code`. Section 6.3 lists this case under `invalid_request`: "The Authorization Server expects a Transaction Code in the Pre-Authorized Code Flow but the Client does not provide a Transaction Code."

## How ProtocolSoup tests it

`issueFromExternalIssuer` checks the offer before fetching any metadata. If the pre-authorized grant has a `tx_code` object (any object, including `{}`, decodes to a non-nil value) and the import request has no `tx_code`, the wallet stops with HTTP 400, `invalid_request` and the description "tx_code is required when tx_code object is present in credential offer". The error carries `tx_code_required`, `tx_code_description`, `tx_code_length` and `tx_code_input_mode` so the wallet UI can prompt for the code. When the user supplies one, `exchangeExternalPreAuthorizedToken` sends it as the `tx_code` form parameter.

`TestIssueFromExternalIssuerRequiresTxCode` imports a pre-authorized offer whose `tx_code` object has a description, length and input mode, without supplying a code. It asserts a `walletAPIError` with status 400 and `tx_code_required` set to true. It does not use an empty `tx_code` object, and it does not check that a supplied code reaches the Token Request.
