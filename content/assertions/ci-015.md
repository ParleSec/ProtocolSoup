## What this requires

OID4VCI 1.0 Section 8.2 requires proofs to "incorporate the Credential Issuer Identifier (audience) and, if the Credential Issuer has a Nonce Endpoint, a c_nonce value to allow the Credential Issuer to detect freshness." Appendix F.4 has the issuer check that "the nonce in the key proof matches the server-provided c_nonce value".

The specification leaves the nonce lifetime to the issuer. Section 13.8 says "A Wallet can continue using a given nonce until it is rejected by the Credential Issuer. The Credential Issuer determines for how long a particular nonce can be used." Treating a nonce as short-lived and single-use is ProtocolSoup's choice, and the registry records it as this requirement.

## Why it exists

Section 13.8 gives the threat: an adversary who obtains a key proof "could potentially replay that proof to a Credential Issuer to obtain a duplicate Credential or multiple duplicates issued to the same key. The c_nonce parameter serves as the main defense against this". A nonce that can be consumed only once means a captured proof is spent as soon as the legitimate request uses it.

## What non-compliance looks like

The issuer checks that the nonce exists, issues the Credential, and only then deletes the nonce. Two concurrent requests carrying the same proof both pass the check and both receive Credentials. The correct response for a reused, expired or unknown nonce is HTTP 400 with `invalid_nonce`, after which the Wallet fetches a new one.

## How ProtocolSoup tests it

Nonce Endpoint values are stored with a five-minute expiry. `consumeCredentialNonce` in `handlers.go` deletes the nonce while holding the plugin mutex, then checks the expiry, so only one request can take a given value. All proofs in one request must carry the same nonce, or the request gets `invalid_nonce`. A failed consumption returns HTTP 400 `invalid_nonce` ("c_nonce is unknown, expired, or already consumed") and emits a Looking Glass security warning with reason `nonce_mismatch_replay_or_expired`.

`TestCredentialNonceConsumptionIsAtomic` obtains one nonce, builds one proof, sends two identical Credential Requests at the same time, and asserts exactly one HTTP 200 and one HTTP 400. It does not check the loser's error code, and no test listed here covers the expiry, so the short-lived half of the statement rests on the five-minute constant in code.
