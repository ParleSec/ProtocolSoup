## What this requires

OID4VCI 1.0 Section 8.2 opens the Credential Request to extension with "Additional Credential Request parameters MAY be defined and used." The sentence that follows is this requirement. The Final Credential Request members are `credential_identifier`, `credential_configuration_id`, `proofs` and `credential_response_encryption`. Any other top-level member is skipped: it is neither an error nor an input to issuance.

Sections 9.1 and 11.1 repeat the same sentence for the Deferred Credential Request and the Notification Request.

## Why it exists

Ignoring unknown members is what makes the extension sentence usable. Without it, an issuer could reject a request only because the Wallet added a parameter the issuer had never heard of.

The other half is just as important. A parameter the issuer does not recognise must have no effect on issuance. The singular `proof` object from pre-Final drafts is not a Final parameter. An issuer that still reads it would accept proofs through a path the Final specification does not define.

## What non-compliance looks like

One failure is an issuer that returns `invalid_credential_request` when the request carries an extension member it does not know. The other is an issuer that treats `proof` as a fallback for `proofs`: it validates the draft object, or issues a Credential when `proofs` is missing.

## How ProtocolSoup tests it

`decodeRequestObject` in `handlers.go` reads every top-level member, rejects any repeated member name with `invalid_credential_request`, and then decodes into the request struct. The struct only has fields for the Final parameters, so unknown members drop out at that point.

`TestCredentialRequestIgnoresUnknownSingularProofWhenProofsPresent` sends an invalid singular `proof` next to a valid `proofs.jwt` array and asserts HTTP 200 with an issued Credential. `TestCredentialRequestIgnoresUnknownSingularProofWithoutProofs` sends only the singular `proof` and asserts HTTP 400 with `invalid_proof`, because `proofs` is absent. Both tests use `proof` as the unrecognised member. The decoders for deferred and notification requests are tested with an arbitrary extension member under CI-017.
