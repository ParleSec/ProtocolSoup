## What this requires

Section 12.2.4 defines `credential_issuer`: "The value MUST be identical to the Credential Issuer's identifier value into which the well-known URI string was inserted to create the URL used to retrieve the metadata. If these values are not identical (when compared using a simple string comparison with no normalization), the data contained in the response MUST NOT be used."

"No normalization" is literal. Case, percent-encoding, default ports and trailing slashes all count, so `https://issuer.example/tenant` and `https://issuer.example/tenant/` are different identifiers. A mismatch means the wallet uses nothing from the response: not the endpoints, not the keys, not the configurations.

## Why it exists

The metadata tells the wallet where to send tokens, proofs and user data, and which keys to trust. If a document fetched for one identifier can speak for another, an attacker who controls any URL the wallet will fetch can claim to be a different issuer. Requiring the document to name exactly the identifier it was fetched for ties the metadata to its location. An exact string comparison avoids depending on URL normalization, which libraries implement differently.

## What non-compliance looks like

The wallet compares the identifiers after normalizing them (lowercasing the host, removing a trailing slash, resolving dot segments) and accepts metadata that the issuer published for a different identifier string. Or it notices the mismatch, logs it, and carries on using the endpoints from the document.

## How ProtocolSoup tests it

`resolveExternalIssuerMetadata` drops a response whose `credential_issuer` is missing or does not match, recording "metadata credential_issuer ... does not match offer ...", and uses nothing from it. The comparison is `sameURLIdentifier`, which compares the two strings exactly. The hosted wallet uses the same exact comparison for Authorization Server `issuer` values (RFC 8414 Section 3.3) and for the RFC 9207 `iss` authorization response parameter.

`TestMetadataCredentialIssuerMismatchRejection` asserts that identical identifiers match and that each of these pairs does not: a different host, a trailing slash, a different letter case in the host, an explicit default port, and a percent-encoded character. Each mismatch is a difference a normalizing comparison would erase. The test exercises the comparison helper rather than a full metadata fetch.
