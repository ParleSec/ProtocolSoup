## What this requires

Section 12.2.4 defines `credential_signing_alg_values_supported` and says its "Algorithm identifier types and values used are determined by the Credential Format and are defined in Appendix A." For `mso_mdoc`, Appendix A.2.2 says the identifiers "correspond to the numeric COSE algorithm identifiers used to secure the IssuerAuth COSE structure, as defined in [ISO.18013-5]."

ES256 is therefore `-7`, a JSON number, not the string `"ES256"`. Appendix A.2.2 also allows a fully specified algorithm such as `-9` when the signing key's curve matches. It notes that the parameter "is primarily informational for the Wallet."

## Why it exists

An mdoc's `IssuerAuth` is a COSE_Sign1 structure, and its `alg` header is a COSE integer. Advertising the same kind of value lets a Wallet compare metadata directly with what it will find in the Credential. JOSE names belong to JWT-based formats, and a value from the wrong registry matches nothing.

## What non-compliance looks like

An issuer reuses its SD-JWT configuration code and advertises `["ES256"]` for an `mso_mdoc` configuration. Or it advertises the right number as a string, `["-7"]`. A Wallet that filters configurations by supported algorithms finds no match and skips a Credential it could have handled.

## How ProtocolSoup tests it

In `registry.go`, both `mso_mdoc` configurations (`MobileDrivingLicenceMsoMdoc` and `MobileDrivingLicenceMsoMdocHAIP`) set `CredentialSigningAlgs` to the integer `-7`. The mdoc issuance driver signs `IssuerAuth` with the P-256 document signer key. The SD-JWT configurations advertise JOSE strings such as `"ES256"` and `"RS256"`.

`TestCredentialIssuerMetadataIncludesMultiFormatConfigurations` fetches Credential Issuer Metadata and checks the formats of five configurations. For both mdoc configurations it asserts that `credential_signing_alg_values_supported` is exactly one element equal to the JSON number `-7`, and that claims sit under `credential_metadata`. It also asserts that SD-JWT configurations use `vct` and that W3C configurations are not advertised. It does not decode an issued mdoc to compare the `IssuerAuth` `alg` header with the advertised value.
