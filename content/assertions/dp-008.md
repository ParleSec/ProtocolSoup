## What this requires

This is check 9 of RFC 9449 Section 4.3. Section 4.2 defines `htu` as "The HTTP target URI (Section 7.1 of [RFC9110]) of the request to which the JWT is attached, without query and fragment parts." The server compares it with the URI the request was received on, with query and fragment removed, and rejects the proof if they differ.

Section 4.3 also says servers SHOULD apply syntax-based and scheme-based normalisation (RFC 3986 Sections 6.2.2 and 6.2.3) before comparing, to reduce false negatives.

## Why it exists

The URI is the other part of the request a proof covers. Section 11.1 relies on it to limit a captured proof to "the same endpoint". Without the check, a proof captured at one endpoint could be replayed at any other endpoint that accepts the same key, such as a token endpoint proof reused at a resource server.

## What non-compliance looks like

A server that skips the check, or compares only the path, accepts a proof minted for another host or endpoint. A server that compares raw strings without normalisation fails the other way: it rejects a valid proof because the client wrote `:443` or an upper-case host.

At a token endpoint the correct response is HTTP 400 with `invalid_dpop_proof` (RFC 9449 Section 5).

## How ProtocolSoup tests it

`dpop.ValidateProof` passes both `htu` and the server's own URI through `NormalizeHTU`, which requires an absolute URI, lower-cases scheme and host, drops the default port for `http` and `https`, removes query and fragment, and keeps the escaped path as it is. The server URI is built from the configured base URL plus the endpoint path, never from the request's `Host` header. The path is not further normalised: dot segments and percent-encoding case are compared as written.

`TestValidateProofHTUNormalizationEquivalence` signs a proof with `htu` of `https://x.test:443/token`, validates it against `https://x.test/token`, and asserts that it is accepted. `TestValidateProofHTUMismatchIsRejected` validates a proof for `/oauth2/token` against `/oauth2/introspect` and asserts rejection. Neither registry test includes a query or fragment; `TestNormalizeHTUStripsQueryAndFragment`, in the same file, covers that by calling `NormalizeHTU` directly.
